日期：2026-10-31。范围：当前网页地面站指挥平台中的实验三。修改前已备份；实验一、实验二源码与本次修改前的备份逐文件比对一致。本次保留独立教学入口、展开指挥台、实时视图、统一资源池和现有任务状态体系。

## 五类任务实际操作

| 任务 | 配置与规划 | 执行与调度 | 成功与失败判定 |
| --- | --- | --- | --- |
| 区域巡逻 | 地图逐点绘制多边形、闭合、拖动顶点或输入坐标；选择飞机、航线间距、扫描方向和巡逻策略 | 生成每架飞机的独立覆盖航线；逐段到点后推进；支持沿边界分段巡逻 | 完成规划航段后返航落地归档；覆盖验收不通过或执行故障记录失败 |
| 目标搜索 | 绘制闭合搜索区域，或设置单点与搜索半径；设置演练目标坐标及单机、双机或人工确认 | 按规划搜索航线飞行；以模拟位置与目标距离判定取得回执；双机要求不同飞机确认 | 未发现目标不能计成功；人工复核可通过或拒绝，随后返航落地 |
| 定点监测 | 设置监测点、选择飞机并调整队列、设置每架到点驻留时间和交接方式 | 首架起飞，其余地面排队；重叠监测提前启动替换机，上架等待替换机到点后返航；顺序模式记录转场空窗 | 按实际到点后的驻留时间判定，记录接力次数和监测空窗；替换前资源检查失败会终止并返航 |
| 物资运输 | 分别设置装载点、途经航点、交付点及模拟物资信息，选择运输飞机 | 各机由自身 Home 起飞，经过装载点、途经点到交付点；支持到点确认或人工签收 | 交付确认通过后返航；拒绝签收或执行故障记录失败 |
| 应急救援 | 设置出发点、事件位置、途经点，分配侦察及救援角色和现场驻留时间 | “先侦察后救援”先启动侦察机；人工通过侦察确认后，后续队列才起飞；支持直接或并行响应 | 现场处置需要人工模拟验收；侦察或最终验收拒绝均记录失败并安全收尾 |

所有任务共用部署次序：**生成方案 → 检查并部署 → 下发模拟航线并检查逐机回执 → 模拟解锁 → 确认模拟起飞 → 执行 / 人工确认 → 返航落地 → 结果归档**。各类型保留独立配置、点位、成员、角色、规划及运行记录。全局态势用于总览，不是第六种执行任务；当前同一时间只执行一个任务，该任务可调度多架飞机。

## 首次体验路径

1. 在实验三选择“进入教学模拟模式”，完成集群启动后进入“多任务协同指挥”，点击“展开指挥台”。
2. 选择左侧任一任务，“任务参数”中展开“模拟演练与验收场景”，点击“载入本任务模拟示例”。示例会配置三架具备当前任务资格的飞机和可执行点位；也可以自行绘制、输入坐标及编组。
3. 选择“正常模拟执行”，点击底部对应的“生成……航线”，在地图和右侧核对逐机航线。
4. 按部署窗口顺序下发、检查回执、解锁、起飞。监测队列及分阶段救援需要明确勾选后续队列自动模拟起飞授权。
5. 执行时可以暂停、继续、终止；搜索人工复核、运输签收及救援现场确认通过底部操作处理。未通过验收时也会返航，不会标记成功。
6. 全部参与机落地、解除任务占用后，查看执行结果并导出 JSON；左侧下方“任务调度”可以查看已归档记录。

验收场景还包含“下发失败”“执行故障（12 秒后）”以及各任务专属的负面结果。它们是明确标注的可重复模拟条件，不是假装接收真实设备故障。

## 两轮设计与交互审查

第一轮关注业务流程：此前统一进度与通用操作无法充分表达五类任务差异。本次增加几何规划、逐机航线、分阶段部署、队列依赖、人工确认和独立失败记录。左侧五张任务卡保持全部可见，下方单独显示调度详情；参数与工具采用地图覆盖面板，底部操作居中且与状态分层；15 架资源表仍在独立大型模态中。

第二轮依据实际运行截图检查：修复切换任务后沿用旧滚动位置、已规划仍显示配置中、1366 视口地图提示与 HUD 交叠及尺寸切换后的视野适配问题。监测运行时优先显示队列和到点驻留；航线生成后提前显示逐机摘要。密集地图标签按屏幕距离简化或按需展示，悬停、选中和操作面板保留无人机身份；不通过移动图标伪造实际坐标。

地图沿用当前实验三独立 MapLibre 二维实现：矢量、卫星和离线米制图层可切换；计划航线、区域填充、顶点、实际轨迹和返航轨迹可管理。地图原生导航每次点击按一级动画缩放，遵循引擎与视口边界，最大 24 级；卫星影像原生最高 19 级，继续放大不产生额外影像细节。测距和坐标拾取不修改任务位置。

## 运行与明确边界

- 本次验证使用 `VITE_DATA_SOURCE=mock npm run dev -- --host 127.0.0.1 --port 5175 --strictPort`；未修改现有 `.env.local` 或原 5173 进程。实验三由注册的 Mock Runtime 执行，不需要后端。
- 这是可操作、可验收的前端教学模拟。未连接真实飞控、摄像头、载荷机构或硬件解锁；不能作为真实飞行系统的生产放行依据。
- 飞行按实际模拟位置和航点推进，含速度、驻留和电量变化；规划采用 5 m 高度分层，但未实现真实空域冲突解算、地形/障碍物避让或安全间距认证。
- 监测每架执行一次队列，返航后不自动补电循环；救援优先级是任务参数，未宣称支持多任务抢占调度。
- 地图瓦片需要网络；不可用时米制坐标与任务流程仍可使用。
- 历史记录保存在当前会话，刷新前可通过 JSON 导出留档；未增加后端持久化。
