# 实验三：五任务调度闭环（Mock 教学模拟）

## 操作

1. `npm run dev`，登录并进入实验三；进入教学模拟、启动集群，等待 15 架机待命。
2. 进入「多任务协同指挥」并展开全屏指挥台；在「无人机资源管理」核对机型、载荷、岗位和 15 架资源，任务运行/返航中的机体不得改装或重复分配。
3. 在指挥台勾选「并发调度」；逐个进入区域巡逻、目标搜索、定点监测、物资运输、应急救援。每次可用「载入本任务模拟示例」核对坐标和角色，也可自行新建、绘制区域/点位、配置资源。
4. 对每项依次生成航线、检查地图中的分机航段、检查并部署、下发模拟航线、模拟解锁、**调度并立即模拟起飞**。监测接力/救援后继起飞需要勾选授权；救援先侦察后响应需在执行中人工确认。
5. 左侧「当前任务」列出所有活动运行，可分别查看、暂停、继续、终止；人工结果确认在各自任务内完成。终止后仍占用资源直到该任务所有参与机落地。全部结束后查看五份归档记录，资源池应全部恢复空闲。

## 修复及验收

- 每项有独立运行 ID、执行态、航线、租赁和归档；并发时切换草稿不会覆盖正在执行的同类型任务。
- 覆盖航线按用户绘制的真实区域等面积分区，每个分区至少两条区内扫描行（若多边形无效/无法连续连接则拒绝规划），不是三架飞机排成一条直线。顺时针巡逻为另一种周界分段策略，不等同于区域覆盖。
- 目标搜索的中继岗位在生成航线时自动选取区域内的驻留点，不占搜索分区、不计目标确认；救援中继提前到响应集结点与事件点之间驻留，不再等待侦察结果才起飞。上述中继随任务收尾自动返航；运输护航仍按原规划执行航线。**没有真实通信转发、无线覆盖、信噪比或失联重路由模型**；此处中继是资源/岗位/航线协同教学演练，不应理解为真实无线链路保障。
- 单机高度上限 120 m 和资源互斥是 Mock 调度规则；不强制检查任务间垂直间隔、也不提供真实避碰，**不是**真实空域许可、避障或物理飞行安全保证。提示的错峰秒数只是建议，当前提交立即起飞，**没有自动排队/自动延迟**。
- 浏览器刷新不会恢复飞行现场；需要重新启动集群和任务。归档和本地偏好与现场状态不同，不能拿来继续实际飞行。

验证命令（使用项目 Node PATH）：`npm run typecheck && npm run build && npm run test:collaboration`；浏览器启动本地 Vite 后执行 `npm run test:collaboration-workflow-browser` 和 `npm run test:collaboration-concurrent-browser`（Playwright-Core 和 Chrome 路径见测试脚本环境变量）。

## 多草稿并发回归（2026-11-02）

并发模式下可先分别载入五个任务示例、生成航线、检查/下发/解锁后点击“保留部署，稍后启动”，再按任意顺序重新打开确认弹窗提交启动；示例编组排除其他未执行草稿已选资源，手动重复加入会明确拒绝。关闭部署只取消当前任务，不会解除其他任务的锁定。物理资源依然一机一任务，返回地面才释放。教学 Mock 不实施全局垂直间隔拒绝，也不自动修改已下发的航线：重叠航线只是演示，**绝不可作为真实无人机避碰或空域安全依据**。
